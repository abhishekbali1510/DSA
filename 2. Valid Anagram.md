# Valid Anagram

> **Problem Link:** [LeetCode 242 - Valid Anagram](https://leetcode.com/problems/valid-anagram/description/)
> **Pattern:** Frequency Counting / Hashing | **Difficulty:** Easy | **Key Idea:** Count character occurrences across both strings

---

### 📌 Problem Description
Given two strings `s` and `t`, return `true` if `t` is an **anagram** of `s`, and `false` otherwise. An anagram is a word formed by rearranging the letters of a different word, using all the original letters exactly once.

---

### 💡 Intuition & Progression

1. **Sorting (Bring Identicals Together):**
   * *Thought:* If two strings are anagrams, sorting their characters alphabetically will produce identical strings.
   * *Trade-off:* Clean to implement, but sorting costs `O(n log n)` time. In languages with immutable strings (like C# or Java), converting strings to char arrays also costs `O(n)` space.

2. **Hash Map / Dictionary (General Character Counting):**
   * *Thought:* Count the frequency of each character in `s`, then decrement using characters in `t`.
   * *Why it's useful:* Works for arbitrary character sets (including Unicode). Takes `O(n)` time, but has dictionary lookup/hashing overhead.

3. **Fixed-Size Frequency Array (Optimal for Lowercase English):**
   * *Thought:* Since constraints specify only lowercase English letters (`a`-`z`), map each character directly to an index (`char - 'a'`).
   * *The "Aha!":* A fixed-size array of size 26 eliminates hash collisions and keeps auxiliary space strictly `O(1)`. If string lengths mismatch, return `false` immediately.

---

### ⚡ Approaches & Trade-offs

| Approach | Time | Space | Pros / Cons |
| :--- | :--- | :--- | :--- |
| **1. Sorting** | `O(n log n)` | `O(1)` to `O(n)`* | Simple to write, but slower than linear; requires string-to-array conversion in immutable languages. |
| **2. Hash Map** | `O(n)` | `O(k)` | Handles any alphabet/Unicode; has slight hashing and boxing overhead. |
| **3. Fixed Array (26)** | `O(n)` | `O(1)` | Fastest and most cache-friendly; space is bounded by the fixed alphabet size (26 integers). |

*\*Note: `k` is the number of distinct characters. Space for sorting depends on whether in-place mutation of the character buffer is possible.*

---

### 📝 Pseudo Code

```text
// 1. Sorting
if length(s) != length(t):
    return false

sort(s)
sort(t)
return s == t

// 2. Hash Map (Unicode-Safe)
if length(s) != length(t):
    return false

counts = empty Map
for char in s:
    counts[char] = counts.get(char, 0) + 1

for char in t:
    if char not in counts or counts[char] == 0:
        return false
    counts[char] = counts[char] - 1

return true

// 3. Fixed Array (Optimal: Lowercase 'a'-'z')
if length(s) != length(t):
    return false

counts = array of size 26 filled with 0

for i = 0 to length(s) - 1:
    counts[s[i] - 'a']++
    counts[t[i] - 'a']--

for count in counts:
    if count != 0:
        return false

return true
